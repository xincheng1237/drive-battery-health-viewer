## Completed checks

- 116 Swift Testing tests pass, including updater routing, duplicate-request suppression, retry, same-version build ordering, signature settings, seven-language copy, and existing charging/health regressions.
- The checked-in feed's exact signed bytes are verified against the embedded Ed25519 public key without private CI secrets; a modified byte is rejected. Its descriptions contain the seven supported languages and its enclosure/version match build 17.
- The opt-in native test separately passes with the actual RootView, temporary preferences/history and read-only hardware scanning. Narrow-window screenshots before/after scrolling confirm content remains below opaque native window chrome.
- A separate QA application compiled the actual production updater adapter. Signed notes, download and archive verification, old build-16 process termination, replacement with build 17 and automatic new-process launch passed. Corrupted archive and tampered signed feed were rejected, leaving build 16 unchanged.
- The synchronized Documents workspace refused the QA app rename with File Provider EDEADLK; the updater reported the error and retained the old app. Successful installation was then verified in a local, non-synchronized temporary directory. Production users should install the app in Applications rather than run from a DMG or a synchronization folder.
- Main application and official pinned Sparkle framework are Universal 2. Helper/Agent are arm64. Both main slices target macOS 13.0. Nested signatures, DMG read-only mount, identifiers/build, installer permissions and third-party payload checks pass. Host signing remains ad-hoc rather than Developer ID notarization.
- Isolated production PowerUI bridge tests still pass. No production App, Helper, Agent, preferences or charging configuration were replaced during updater QA. No real calibration cycle was forced.

Remote CI and merge evidence are linked from the release PR. The signed feed requires its immutable archive to be uploaded before the feed is made live. See [in-app update design](../IN_APP_UPDATES.md) and [calibration support boundaries](../SYSTEM_CHARGING_STATES.md).
