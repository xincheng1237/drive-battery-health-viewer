## Checks completed locally

- 108 Swift Testing tests pass in two independent scratch directories, including state transitions, old JSON, status freshness/configuration matching and genuine-error separation.
- The actual Objective-C bridge passes isolated fake-client/notification tests for system overrides, calibration, unsupported builds, failed reads and pauses arriving during engagement.
- Actual SwiftUI notices rendered in seven languages, light and dark; native calibration glyph geometry checked.
- Main executable and smartctl are Universal 2 (arm64 + x86_64); Helper and menu-bar Agent are arm64. Both main executable slices target macOS 13.0.
- Fresh ZIP and DMG generated from the same application bundle. DMG checksum, read-only mounted bundle, version/build/identifier, nested signatures, installer permissions and third-party payload hashes verified by the build scripts.
- Bundle and executable signatures pass `codesign --verify`; these are ad-hoc signatures, not Developer ID notarization.
- The production reader was probed read-only on macOS 15.8.1 (24H212): no current gauging suspension or system full-charge override was reported. No control calls were made.

Remote CI and merge status remain independently inspectable in [pull request #6](https://github.com/xincheng1237/drive-battery-health-viewer/pull/6).

## Limits

Calibration mapping is gated to the inspected build 24H212. No fresh complete hardware calibration/recovery cycle was forced. Tests and an inactive live read do not establish all-model, all-version or full-cycle compatibility. The installed application and root Helper were not replaced during release preparation. See [system charging states](../SYSTEM_CHARGING_STATES.md).
